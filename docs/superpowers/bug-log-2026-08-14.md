# Bug log — codebase hardening pass, 2026-08-14

Every bug found while going through the scripts before new feature work begins. Movement code
(`PlayerController.Move/Look/Jump/FixedUpdate`, `PlayerGroundCheck`) was deliberately skipped —
it is being replaced wholesale in A2 by the Quake 3 `CharacterController` port.

**Severity key:** 🔴 crash or broken gameplay · 🟠 wrong behaviour · 🟡 latent / robustness · 🔵 performance

---

## 🔴 Crashes

### 1. `Scoreboard.RemoveScoreboardItem` — `KeyNotFoundException`
`Destroy(scoreboardItems[player].gameObject)` indexed the dictionary directly. Any
`OnPlayerLeftRoom` for a player who was never added — which happens for anyone joining and
leaving while the scoreboard is initialising — threw and killed the callback.
**Fix:** `TryGetValue` and return early.

### 2. `SpawnManager.GetSpawnpoint` — `IndexOutOfRangeException`
`spawnpoints[Random.Range(0, spawnpoints.Length)]` with an empty array: `Random.Range(0, 0)`
returns `0`, so it indexed `[0]` of an empty array. Silently fatal to spawning.
**Fix:** explicit empty check returning null, plus an error at `Awake` if no spawnpoints exist,
and guards at both call sites.

### 3. `PlayerController.Awake` — `NullReferenceException` on a network race
`PhotonView.Find(...).GetComponent<PlayerManager>()` chained off a lookup that returns null when
the owner's `PlayerManager` view is not yet registered on that client. The throw aborted the rest
of `Awake`, leaving the object half-initialised.
**Fix:** `ResolvePlayerManager()` reports and returns false; retried from `Die()`.

### 4. `PlayerManager.Find` — `InvalidOperationException`
`SingleOrDefault` **throws** when more than one match exists, converting a cosmetic desync into a
hard exception.
**Fix:** `FirstOrDefault`.

### 5. `PlayerManager.Die` — throw on a null controller
`PhotonNetwork.Destroy(controller)` with `controller == null` (reachable whenever
`CreateController` bailed) threw, leaving the player permanently dead with no respawn.
**Fix:** null check, and clear the field before recreating.

### 6. `PlayerController.RPC_TakeDamage` — unguarded kill credit
`PlayerManager.Find(info.Sender).GetKill()` dereferenced a possibly-null result, so a missing
killer took the victim's death down with it.
**Fix:** null check with a warning; the death still registers.

## 🟠 Wrong behaviour

### 7. Vertical aim was never networked
`Look()` puts yaw on the root (replicated by `PhotonTransformView`) but pitch on `cameraHolder`,
which had **no components at all**. Remote players never saw anyone aim up or down.
**Fix:** `PlayerController` implements `IPunObservable`, sending pitch as a single float on the
existing root `PhotonView`. See the A1 spec for why this beats a fourth `PhotonView`.

### 8. `SingleShotGun` — you could shoot yourself
Every object in the project is on layer 0 and the raycast started at the camera position, inside
the player's own capsule collider.
**Fix:** ignore hits whose `PhotonView.Owner` is the shooter. Done by ownership rather than layer
mask, since the project has no Player layer to mask against.

### 9. `SingleShotGun` — shots consumed by trigger volumes
The raycast honoured triggers by default, so it could hit the `GroundCheck` trigger — a volume
parented under the player, right at the muzzle — and stop there, dealing no damage.
**Fix:** `QueryTriggerInteraction.Ignore`.

### 10. `SingleShotGun` — damage missed anything but the root
`hit.collider.gameObject.GetComponent<IDamageable>()` finds nothing when the collider sits on a
child object.
**Fix:** `GetComponentInParent<IDamageable>()`.

### 11. `SingleShotGun` — unbounded range
No `maxDistance`, so shots hit anything on an infinite ray.
**Fix:** serialized `maxRange`, default 200.

### 12. `Launcher.cachedRoomList` — stale rooms, never cleared
The dictionary was `static` and never cleared on leaving the lobby or disconnecting. Closed rooms
stayed listed for the process lifetime, and in the editor survived across play sessions. Clicking
one failed.
**Fix:** instance field, cleared on `OnJoinedLobby` / `OnLeftLobby` / `OnDisconnected`; empty rooms
also dropped.

### 13. `Launcher` — failed room joins hung forever
`OnCreateRoomFailed` existed but `OnJoinRoomFailed` did not. Joining a full or closed room left the
player on the loading screen with no error and no way back.
**Fix:** implemented, routing to the error menu.

### 14. `Launcher` — silent disconnects
`OnDisconnected` was not implemented, so a dropped connection left whatever menu was open on
screen with no indication anything was wrong.
**Fix:** implemented, showing the `DisconnectCause`.

### 15. `Launcher.CreateRoom` — no player cap
`PhotonNetwork.CreateRoom(name)` passed no `RoomOptions`, so rooms had unlimited players.
**Fix:** `RoomOptions` with a serialized `maxPlayersPerRoom`, default 8.

### 16. `PlayerNameManager` — empty nicknames persisted
`PlayerPrefs.HasKey` is true for a key holding an empty string, so an empty nickname was loaded and
applied. Players appeared blank on scoreboards and nameplates with no way to recover short of
clearing PlayerPrefs. Names were also never trimmed.
**Fix:** whitespace check rather than `HasKey`, trim, and refuse to persist empty.

### 17. `RoomManager` — duplicate managers after a rejoin
Returning to the Menu scene creates a second `RoomManager`. `Awake` marks it for destruction, but
`Destroy` is deferred to end of frame, so its `OnEnable` still ran and subscribed a **second**
`sceneLoaded` handler — after one rejoin, every player spawned two `PlayerManager`s.
**Fix:** `OnEnable` bails when `instance != this`.

### 18. `Path.Combine` built the networked prefab key
`Path.Combine("PhotonPrefabs", "PlayerManager")` yields a backslash on Windows. It resolves there,
but this string is sent over the network as a Resources key and would break any mixed-platform room.
**Fix:** explicit forward-slash constants at both call sites.

### 19. `MenuManager.OpenMenu` — typos blanked the screen
An unrecognised menu name closed every menu and opened nothing, with no diagnostic.
**Fix:** error log naming the missing menu.

### 20. `Billboard` — could face the wrong camera
`FindObjectOfType<Camera>()` returns an *arbitrary* camera. Remote players' cameras are destroyed
in `PlayerController.Start`, but during that window a nameplate could latch onto the wrong one.
`Camera.main` was not an option — the player camera is `Untagged`.
**Fix:** `PlayerController.LocalCamera` static, set when `IsMine`, cleared on destroy.

### 21. `UsernameDisplay` — NRE and pointless work when `IsMine`
Disabled the object then **kept executing** to touch `playerPV.Owner`, which can be null on a
freshly instantiated object.
**Fix:** early return when `IsMine`; null-safe nickname with a short retry while `Owner` resolves.

### 22. `ScoreboardItem` — placeholder text before first score
Players with no `kills`/`deaths` custom property yet showed whatever text the prefab shipped with.
**Fix:** default to `"0"`.

## 🟡 Robustness

### 23. `Scoreboard.AddScoreboardItem` — leaked rows on duplicate add
Re-adding an existing player overwrote the dictionary entry and orphaned the old GameObject,
leaving a row that could never be removed.
**Fix:** ignore adds for players already present.

### 24. `Launcher` — duplicate rows on same-frame rebuilds
Both list rebuilds walked the container's children and called `Destroy`, which is deferred to end
of frame. Two rebuilds in one frame produced duplicates.
**Fix:** track spawned rows in lists and clear those.

### 25. Missing singleton guards
`Launcher`, `MenuManager`, `SpawnManager` all did a bare `Instance = this`, so a second instance
silently hijacked the static. None cleared it on destroy, leaving dangling references.
**Fix:** guard on construction, clear on destroy.

### 26. `Spawnpoint.Awake` — unguarded reference
`graphics.SetActive(false)` threw when unassigned, aborting scene-load initialisation.
**Fix:** null check.

### 27. `RoomListItem.OnClick` — null `Launcher.Instance`
`Launcher` is destroyed on scene load; a click during the transition dereferenced null.
**Fix:** guard with a warning.

### 28. `SingleShotGun` — string RPC name
`PV.RPC("RPC_Shoot", ...)` would not survive a rename.
**Fix:** `nameof(RPC_Shoot)`.

## 🔵 Performance

### 29. `PlayerManager.Find` — full scene scan per kill
`FindObjectsOfType<PlayerManager>()` on every call, and it is called on every kill.
**Fix:** static `Dictionary<Player, PlayerManager>` registry, with the scan kept only as a fallback
for the window before `Owner` resolves.

### 30. `Billboard` — per-frame `FindObjectOfType` while unresolved
Ran a full-scene type search every frame until it found a camera, on every nameplate.
**Fix:** reads a static; also moved to `LateUpdate`, since facing a camera from `Update` leaves the
nameplate a frame stale and visibly swimming. `LookAt` + 180° `Rotate` collapsed into one
`Quaternion.LookRotation`.

### 31. `SingleShotGun.RPC_Shoot` — allocation per shot
`Physics.OverlapSphere` allocates a new array on every call.
**Fix:** `OverlapSphereNonAlloc` into a shared static buffer.

### 32. `Launcher` — Linq on an array
`using System.Linq` and `players.Count()` where `players.Length` was available.
**Fix:** removed; `System.Linq` dropped from that file.

### 33. Photon serialisation rate
Verified from `PhotonNetwork.cs`: `sendFrequency = 33`ms (≈30 Hz) but `serializationFrequency =
100`ms — remote positions and aim updated only **10×/second** and were interpolated between.
**Fix:** `SerializationRate = 20`, `SendRate = 30`.

### 34. Photon region hard-pinned
`FixedRegion: uae` forced every player onto the UAE cluster regardless of location.
**Fix:** unpinned; PUN selects by ping. See the risk note in the A1 spec — if players are
geographically split, one explicit shared region beats auto.

### 35. Unused `using` directives
Nearly every file carried `System.Collections` / `System.Collections.Generic` from the default
Unity template without using them. `PlayerManager` also kept `System.IO` after `Path.Combine` was
removed.
**Fix:** trimmed across all touched files.

### 36. Dead components on the player prefab
A `Point` light imported from the `.3DS` with intensity 271 and **range 0** — lighting nothing while
still being processed on every player. Disabled.
*(The root `MeshFilter`/`MeshRenderer` were checked and are already disabled — inert, left alone.)*

## Deliberately not fixed

- **Movement** — `PlayerController.Move/Look/Jump/FixedUpdate` and all of `PlayerGroundCheck.cs`.
  Being deleted in A2 when the Quake 3 `CharacterController` port lands.
- **No Player / Ground layers.** The correct fix for several raycast bugs is proper layers and a
  layer mask, but that means editing `TagManager.asset` and reassigning layers across prefabs and
  scenes. Worked around by ownership checks and `QueryTriggerInteraction.Ignore`. Worth doing
  properly during A2.
- **The late-join visibility bug.** Still open — see the A1 spec. Diagnosed as far as "the inbound
  Photon path is dead on clients already in the game scene", pending a live overlay reading.
